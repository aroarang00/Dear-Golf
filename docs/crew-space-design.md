# 크루(친구 소수 그룹) 공유 앨범 — 설계 스케치

> 작성 2026-06-22. 상태: 설계 중 / 구현 전.
> 목적: 친한 친구 **소수 그룹**이 함께 쓰는 **공유 앨범(사진·동영상 + 댓글)**. 단체/모임을 흡수하기 전, 가벼운 토대.
> 큰 단체는 아직 무리 → **소수 친구 그룹**으로 시작(전원 동등). 채팅은 **빼고**(1:1 DM이 이미 담당), **앨범+댓글**에 집중.

## 0. 범위 (의도적으로 가볍게)
- **넣음**: 크루(공유 멤버십) + 게시물(사진/동영상 + 캡션) + 게시물 댓글.
- **뺌**: 그룹 채팅(DM이 대신), 운영자 권한(전원 동등), 큰 단체 흡수.
- **CF 0**(올림 알림은 옵션·후속), 새 패러다임 0 — 전부 기존 패턴 복사.

## 1. 진입점 — 홈 우상단 DM 옆/아래 **크루 아이콘** (DM의 형제)
- DM(💬)은 **홈 우상단 헤더로 일원화**됨(`HomeScreen.js:105` — 테스터 "친구 탭은 불편" 피드백으로 친구 탭 💬 제거 후 홈으로 이동).
- 크루 = DM과 같은 **"프라이빗 소통" 식구** → **같은 자리(DM 아래)에 형제 아이콘**(반투명 버터 동그라미 동일 톤)으로 진입.
- ★친구 탭이 아니라 **홈에 두는 이유**: DM을 친구 탭→홈으로 옮긴 *바로 그 피드백*과 동일. 프라이빗 소통은 홈 코너로 모은다(친구 탭 반복 회피).
```
홈 우상단:  [ 💬 DM ]
            [ 👥 크루 ]   ← DM 아래 형제 아이콘(새 글 점·안읽음 톤 동일)
```
- 주의: 우상단은 iOS 확대 시 혼잡([[responsive-zoom-backlog]]) — 기존 DM 줌 처리와 함께 세로로 정렬.

### 친구 그룹과 무관 (왜 독립인가)
친구 **그룹칩은 각자 비공개·서로 다름**(내 "수요회" ≠ 친구 "수요회") → 공유 크루의 닻이 못 됨. 크루는 **독립 입구(홈 아이콘)·독립 멤버십**.

## 2. 화면 흐름 — 3단
```
홈 [👥] → ① 내 크루 리스트 → ② 크루 앨범(게시판) → ③ 게시물 상세(+댓글)
```
- ①②③ 각 1겹씩 쌓이되 홈 위 Modal/스크린 푸시 — 깊은 중첩 아님(DM 모달과 동일 레벨에서 엶).
- 푸시/알림(옵션, 후속)은 ②로 바로 라우팅.

## 3. 화면 구성
### 3.0 내 크루 리스트 (아이콘 진입 첫 화면)
- 헤더: `크루` + `⊕`(만들기).
- **내가 멤버인 크루 목록**(`memberUids array-contains me`) — 세로 리스트: 대표 이미지·이름·멤버 수·**새 글 점**.
- **초대받은 크루**는 상단에 "초대됨" 묶음 → 수락/거절.
- 비었으면 "친구들과 첫 크루를 만들어보세요".

### 3.1 크루 앨범 (게시판)
- **헤더**: 크루 이름 · 멤버 아바타 줄 · `⚙`(멤버 초대/관리·나가기)
- **본문**: 게시물 피드 — 사진/동영상 썸네일 **그리드**(또는 세로 카드). 각 항목: 미디어 + 캡션 1줄 + 💬N
- **올리기**: 상단/FAB `＋` → 미디어 선택(사진·동영상 다중) + 캡션 → 게시
- **빈 상태**: "첫 사진을 올려보세요"

### 3.2 게시물 상세
- 미디어 크게(스와이프·동영상 재생) + 캡션 + 작성자/시간
- **댓글**: roundup 댓글 UI 재사용. 본인 댓글 삭제.
- 본인 게시물: 삭제(미디어 storage 정리는 후속).

### 3.3 크루 만들기 / 초대
- `⊕` → **이름 입력 + 친구 초대**(친구 목록 다중 선택).
  - 편의: "그룹에서 불러오기"로 **초대 대상 프리필만** 가능(`resolveGroupAudience`) — 단순 다중선택 채우기, **연결·저장 없음**(그룹↔크루 매핑 안 함).
- 생성 = `scheduleGroups`식: 만든 사람만 멤버, 나머지는 초대(audience).
- 초대받은 사람: **내 크루 리스트** 상단 "초대됨" + 알림(옵션) → 수락 시 멤버 합류.

## 4. 데이터 모델 (신규 — 컬렉션 1 + 중첩 서브 2)
```
crews/{crewId}                 // 멤버십 — scheduleGroups 패턴 복사
  name, creatorUid             // creatorUid = 씨앗(권한 아님, 전원 동등)
  memberUids: [uid]            // 수락한 멤버 (셀프토글 합류)
  audienceUids: [uid]          // 초대받음(미수락)
  declinedUids: [uid]
  names: { uid: 이름 }         // 표시용
  createdAt, updatedAt
  /posts/{postId}              // 게시물 — 사진/동영상 + 캡션
    authorUid, caption,
    media: [ { url, type:'image'|'video', poster? } ],
    createdAt
    /comments/{commentId}      // 댓글 — roundup comments 패턴 복사
      authorUid, body, createdAt
```
- 멤버십 = 단일 진실원 `memberUids`. 초대/수락/탈퇴는 셀프토글(규칙 위조방지).
- **친구 그룹(friendGroups)과는 무관** — 크루는 독립 공유 엔티티. 그룹은 그대로 비공개 필터 라벨로 둠(연결 안 함). 그룹은 만들 때 초대 프리필 편의로만 쓰일 수 있음.
- 입구(내 크루 줄)는 `crews` where `memberUids array-contains me` 쿼리로 채움 — 모두에게 동일·안정.

## 5. 재사용 매핑 (거의 다 복사)
| 조각 | 재사용처 | 신규 |
|---|---|---|
| 멤버십(초대/수락/탈퇴) | `scheduleGroups` 규칙·셀프토글(`scheduleShares.js`) | 컬렉션·규칙만 |
| 사진+**동영상** 업로드 | `uploadRoundMedia`(`roundMedia.js`) — 영상+포스터까지 처리. 경로 `rounds/{uid}/` | **storage 규칙 0** |
| 댓글 | roundup `comments`(생성=본인·삭제=본인·read=멤버) | 서브컬렉션 규칙 |
| 미디어 뷰어·그리드 | 기존 다이어리/공유 카드 컴포넌트 | 조립 |
| 초대 대상 선택 | 친구 그룹 프리필(`resolveGroupAudience`, `RoundupCreateModal` 패턴) | 조립 |

→ 새로 짓는 건 **컬렉션 1 + 서브컬렉션 2 + 규칙 1세트 + 화면 3(목록행·앨범·상세) + 만들기/초대.** CF 0.

## 6. 권한 모델 (전원 동등)
- 게이트 = **크루 멤버십**(친구 관계 아님 — 그룹엔 친구의 친구가 섞일 수 있음. 초대/수락이 동의이므로 안전).
- 멤버 누구나: 게시물 올리기·댓글·자기 것 삭제·친구 더 초대·본인 탈퇴.
- 운영자 없음. crew read/write = `memberUids` 기반.

### 운영 규칙 (확정 2026-06-22)
| 항목 | 규칙 |
|---|---|
| **생성** | **누구나** 크루 만들기 가능 |
| **입장** | **초대만**(공개 가입·발견 없음). audience→member 셀프 수락 |
| **탈퇴** | **자유**(셀프, 언제든). 마지막 1명 탈퇴 시 빈 크루 처리는 후속 |
| **이름** | **만든 사람이 자유 지정**. 리네임 권한(만든사람만 vs 전원)은 후속 — v1 만든사람 |
| **그 외 행동** | 전원 동등(초대·게시·댓글) |

### 규칙 초안 (스케치)
```
match /crews/{crewId} {
  allow read:   member or audience
  allow create: creatorUid==me, memberUids==[me], declinedUids==[]
  allow update: 초대추가(member가 audience+) / 수락(audience→member 셀프) / 탈퇴(self)   // scheduleGroups 복사
  match /posts/{postId} {
    allow read:   crew 멤버(get(crews/{crewId}).memberUids 포함)   // mealSuggestions의 부모 get 선례
    allow create: authorUid==me && 멤버
    allow delete: authorUid==me
    match /comments/{commentId} {
      allow read:   멤버
      allow create: authorUid==me && 멤버
      allow delete: authorUid==me
    }
  }
}
```

## 7. 시너지 — 단체 전체창과 공용
이 **"미디어+댓글 앨범" 컴포넌트는 단체 전체창의 사진 부분(`event-model.md §12 G`)과 사실상 동일.**
→ 한 번 만들어 **크루 앨범 / 단체 전체창** 양쪽 재사용. 크루를 먼저 만들면 단체에도 그대로 이득.

## 8. 미해결 / 후속
1. **미디어 orphan 정리** — 동영상 용량 큼·영구 저장. 크루/게시물 삭제 시 storage 정리(TTL/CF 후순위).
2. **올림 알림(푸시)** — 새 게시물 시 멤버에게 알림. `onDocumentCreated` 트리거 1개(옵션, `onScheduleGroupCreated` 패턴). v1은 인앱 점만.
3. **읽음(새 글 점) 기준** — 마지막 본 시각 per-uid(로컬 or crew에 lastSeen 맵). 가볍게 로컬부터.
4. **크루 인원 상한** — 소수 전제(예 ≤12). 상한·UI 경고.
5. **친구 끊김 시** — 크루 멤버는 친구 무관(멤버십 기반)이라 자동 영향 없음. 표시 이름만 names 맵 폴백.
6. **친구 그룹과 분리 확정** — 그룹은 비공개·각자 달라 공유 크루의 닻이 못 됨(§1 정정). 입구는 "내 크루" 전용 줄(크루 멤버십 기반). 그룹은 초대 프리필 편의로만.
7. **진입점 확정** — **홈 우상단 DM 아래 형제 아이콘**(DM과 같은 프라이빗 소통 식구). 친구 탭은 테스터가 불편하다던 자리라 회피(`HomeScreen:105`). 기록 탭 노출은 후속 검토.
8. **미디어 한도(확정)** — 게시물당 **합쳐 10개**(사진+영상 혼합 허용), 그중 **동영상은 1개까지**(무거움), **영상 30초**. 다이어리 `MAX_PHOTOS=10`·`MAX_VIDEO_SEC=30`·picker 재사용 + "동영상 1개" 가드만 추가.
9. **공지(확정)** — **텍스트만**(공유용 미디어 글과 분리), **누구나(멤버) 작성**(전원 동등), **1개만·최신이 기존 대체**(핀 하나 유지).
10. **사진 저장 / 전송 아이콘** — 남이 올린 미디어는 기기에 **저장**(expo-media-library, 상세 미디어 우하단 ⤓). 댓글 전송은 **종이비행기**(DM '편지'와 구분).
11. **보관 기간(확정)** — **영구 보관(수동 삭제만).** 앨범=추억 보관함이라 자동 만료 X(임시 데이터와 성격 다름). 비용은 per-게시물 캡(동영상 1개·30초·사진 압축)으로 억제. 정리=수동 삭제 + 크루 해체(전원 탈퇴) 시. 비용 이슈 생기면 후속으로 "동영상만 1년 TTL" 검토.
12. **인원 한도(확정)** — 크루당 **최대 20명**. 소수 모임 정서 + memberUids 배열·푸시 fan-out 부담 적정선. 초과 시 초대 차단.
13. **신고(확정)** — 친구 전용이라 기능적 필요 낮으나 **스토어 UGC 정책(Apple 1.2·Google) 대비 최소 신고 포함**: 게시물·댓글 `⋯`→신고(기존 `contentReports` 재사용) + 차단=기존 친구 차단 재사용 + 크루 나가기.
14. **순수 소통(확정)** — 크루엔 **점수·다이어리·기록 기능 안 넣음**(피드/단체와 경계). 사진·영상·댓글·공지 소통 전용. 프로필(아바타) 탭 → 메시지(DM, 친구라 가능).
15. **비속어 필터** — 댓글·글·크루이름에 기존 `containsProfanity`·`PROFANITY_BLOCK_MESSAGE` 재사용.
16. **표시 이름 = 보는 사람 각자의 별명** — 저장은 `authorUid`(+닉네임 폴백), 표시 시점에 `friendDisplayName(friendMeta, uid, 닉네임)`으로 각자 별명 resolve([[friend_groups]]). ★별명은 owner-private라 **저장·전파 금지**(companions·라운지 이름과 동일). mock은 하드코딩, 실연결 시 적용.
17. **크루 개수(확정)** — 목록은 내가 멤버인 크루 **전부 표시**(즐겨찾기↑·최근활동순, 스크롤, `memberUids array-contains` 쿼리 1번). 생성·가입은 **1인당 소프트 캡 30개**(남용·비용 방지, 초과 시 안내).
18. **글자 한도(확정)** — 크루명 **10자**(만들기·이름변경), 게시물 글 1000 / 공지 500 / 댓글 300자.

## 9. 단계 (Phase 1 = 거의 순수 추가 — 기존 변경 0)
- **Phase 1** — 크루(멤버십·초대/수락) + **홈 우상단 DM 아래 크루 아이콘 → 크루 리스트** + 앨범(사진/동영상 올리기) + 게시물 댓글. *기존 파일 손대는 곳 = HomeScreen 헤더 아이콘 1개뿐, 나머지는 전부 신규 파일.*
- **Phase 2** — 올림 푸시 알림 + 새 글 점 정교화 + orphan 정리.
- **Phase 3(검증 후)** — 단체/모임 흡수로 확장(이 크루를 단체팀에 연결).
