## ⭐ "내 테스트는 됐는데 실사용자한테선 안 되는" 갭

> 진짜 위험은 경계값이 아니라 **내 테스트 환경이 실사용 환경을 못 재현해서 버그가 가려지는 것**.
> 아래 5가지 차이가 "잘 되던 게 안 되는" 사고의 원인. 검증은 이 갭을 일부러 만들어서 한다.

| 내 테스트 환경 | 실사용자 환경 | 가려지는 버그 |
|---|---|---|
| **1대 기기 / 1계정** | 여러 기기·여러 사람 동시 | uid 불일치, 권한거부(users uid 필드 누락), 동시 정원초과, 친구 양방향 desync |
| **dev 빌드 (`__DEV__` 우회)** | release 빌드 | 생년월일 미수신 게이트, 코스이동, 사진권한 — dev가 전부 가림 |
| **이미 쌓인 로컬 데이터** | 프레시 설치 (allowBackup=false) | 첫 진입 빈 상태, 복원 안 됨, 권한 첫 요청 |
| **안정적 와이파이** | 끊기는 LTE·지하·필드 | 업로드 중단, 멱등성 깨짐(중복 푸시·중복 일정), 트랜잭션 경합 |
| **내 데이터만 깨끗** | 옛 스키마·고아·kakaoId 누락 데이터 | 코스 오매칭, 고아 카드, 옛 전체공개 글 read 거부 |

**효과 큰 검증 습관 ("가린다"의 정체 없애기):**

- [ ] 🔴 **dev 우회 끄고 release처럼** 테스트 (특히 카카오 19세 게이트 `__DEV__` 분기)
- [ ] 🔴 **2계정·2기기로 cross-user 검증** — 초대장 수신·친구 수락·모집 참여/확정·차단 (uid 안정화 이후 필수)
- [ ] 🔴 **매 빌드 프레시 설치로만 검증** — 기존 로컬데이터가 버그를 가림
- [ ] 🟠 **비행기모드 토글로 네트워크 단절 주입** — 업로드·참여·확정 도중
- [ ] 🟠 **옛/지저분한 데이터로 테스트** — kakaoId 없는 옛 기록, 고아 일정, 옛 전체공개 글
